# Crafty Puns — Setup Guide

## 0. What this theme is

Generated from `craftypuns-topical-map.xlsx` (the Topical Map, Use Hubs, Outer
Section, Header & Footer, Site Pages, H2 Template and Seasonal Calendar sheets).
Regenerating the data or content after editing the xlsx:

```bash
cd scripts
python parse_xlsx.py      # re-parses the xlsx into data/*.json, validates row counts
python generate_wxr.py    # rebuilds ../content-import.xml from data/*.json + p1_content.py
```

## 1. Build the CSS (you run this — Node wasn't available in the build environment)

```bash
cd craftypuns-theme
npm install
npm run build
```

This compiles `src/tailwind.css` → `assets/css/style.css` (minified), which
`functions.php` enqueues. **Confirm `assets/css/style.css` exists and is non-empty
before zipping** — the theme will load without it, but unstyled.

## 2. Zip the theme

Zip the **contents** of `craftypuns-theme/` (not the `scripts/` or `data/`
folders need to ship, but leaving them in is harmless — WordPress ignores
non-PHP/theme files) so that `style.css` and `functions.php` sit at the root
of the zip, e.g.:

```bash
cd craftypuns-theme
zip -r ../craftypuns-theme.zip . -x "scripts/*" "data/*" "node_modules/*"
```

## 3. Upload & activate

1. WP Admin → **Appearance → Themes → Add New → Upload Theme**.
2. Upload `craftypuns-theme.zip`, install, and **Activate**.

## 4. Import content

1. WP Admin → **Tools → Import → WordPress → Install Importer** (if not already installed).
2. Upload `content-import.xml` (at the theme root, generated by `generate_wxr.py`).
3. On the import screen, assign all content to an existing user (e.g. your admin
   account) — the WXR's placeholder author email is `placeholder@craftypuns.net`.
4. Check "Download and import file attachments" — there are none in this import,
   so it's a no-op, but leaving it checked is harmless.
5. Run the import. You should end up with:
   - **39 categories** (10 hub + 29 sub-hub)
   - **9 pages** (About Us, Contact, Privacy Policy, Terms & Conditions, Disclaimer,
     Cookie Policy, Editorial Guidelines, Our Authors, DMCA)
   - **277 posts** (245 topic pages + 13 use-hub pages + 19 outer-section pages)

## 5. Assign menus

WP Admin → **Appearance → Menus**:

- Create a menu, assign it to **Primary Menu**, and add the hub category pages
  + the use-hub/outer pages listed in the Header & Footer sheet's HEADER block
  (By Topic / By Use / Learn / Riddles / Meanings / Pun Generator). Until you do
  this, the site falls back to a hardcoded mega-menu matching that sheet exactly
  (see `inc/fallback-menus.php`), so the site works correctly either way.
- Create a second menu, assign it to **Footer Menu**, same fallback logic applies
  (see `craftypuns_fallback_footer_menu()`).

## 6. SEO plugin (recommended, not required)

Install **Rank Math** or **Yoast SEO** for the XML sitemap — a theme-only sitemap
isn't reliable without a plugin or cron handling it. Both plugins' title/meta-description
postmeta fields are already populated by the WXR import (alongside the theme's own
`_seo_title`/`_seo_description` fallback), so there's nothing to redo once you activate
either plugin — see `inc/seo-meta.php`.

## 7. Legal pages — have a lawyer review

Privacy Policy, Terms & Conditions, Disclaimer and Cookie Policy ship as complete,
usable boilerplate for a humor site running ads and a free tool, but they are **not**
lawyer-reviewed. Review all four before launch.

## 8. Placeholders to replace before launch

- `placeholder@craftypuns.net` — used throughout (Contact page, DMCA page) — replace
  with your real contact/DMCA email.
- "Our Authors" uses generic "Staff Writer" placeholders, no real names invented.
- Facebook/Instagram footer social links are omitted (the sheet marks them "Add if
  active") — add them in `inc/fallback-menus.php` → `craftypuns_fallback_footer_menu()`
  once those accounts exist.
- `screenshot.png` is a plain placeholder graphic — swap for a real screenshot once
  the site is live and styled.
- Front page "Coming Up" seasonal module (`front-page.php`) is hardcoded to the 3
  nearest events as of the October 2026 build (Halloween → Thanksgiving → Christmas).
  Update that block directly as each event passes — see the Seasonal Calendar sheet
  for the full year's schedule and lead times.

## 9. Content status — real puns vs. TODO placeholder

Every post has correct SEO metadata, categories, and FAQ schema. The H2 pun
sections themselves are real, original content for the pages below; every other
post (including the rest of the ~27 total P1-priority pages) currently has
`<!-- TODO: puns content -->` in each H2 section instead.

**Still TODO — P1 outer-section pages (3):**

What Is a Pun?, Types of Puns, How to Write a Pun

To add real content for any page: write it into `scripts/p1_content.py` (topic
pages) or extend `render_simple_content()` in `scripts/generate_wxr.py` (use-hub/
outer pages), then re-run `python generate_wxr.py` and re-import, or hand-edit the
post directly in WP Admin.

## 10. Known gaps / judgment calls made during generation

- Use-hub and outer-section posts don't get a WordPress category assigned (the
  xlsx only defines categories for the Topical Map's Hub/Sub-hub structure).
- The 8 sub-hubs marked "Served by topic post" in the Site Pages sheet (Plant,
  Space, Science, Christmas, Halloween, Sport, School, Name Puns) are **not**
  separate categories — their sibling posts attach directly to the parent hub
  category, matching the sheet's instruction to add a "More [X] Puns" links block
  on the topic post itself instead. That links block is not yet built into
  `single.php` — currently only the Contextual-Bridges-based "Related Puns" block
  covers this; consider adding a dedicated "More in this topic" block if the
  8 served-by-post pages need deeper internal linking.
